*nvim-conan.txt*            nvim-conan for Neovim            *nvim-conan*

Author: mm4cN

nvim-conan integrates Conan workflows into Neovim with a single |:Conan|
command, interactive Telescope pickers, and project-local configuration.

1. Requirements                                       *nvim-conan-requirements*

- Neovim 0.12 or newer
- Conan 2.x available on your PATH
- telescope.nvim

Conan is not installed automatically. Install it manually and make sure
`conan --version` works in the same environment where Neovim starts.

==============================================================================
2. Installation                                       *nvim-conan-installation*

Example with lazy.nvim: >
  return {
    "mm4cN/nvim-conan",
    dependencies = {
      "nvim-telescope/telescope.nvim",
    },
  }
<

==============================================================================
3. Setup                                                     *nvim-conan-setup*

Call `setup()` once during startup: >
  require("conan").setup()
<

The plugin:
- checks whether `conan` is executable
- defines the |:Conan| user command
- detects `conanfile*.py` and `conanfile*.txt` in the current working directory
- creates a configuration when a Conan project is detected and none exists

==============================================================================
4. Commands                                               *nvim-conan-commands*

                                                        *:Conan*
The main entry point is: >
  :Conan {subcommand} [args]
<

Available subcommands:

`install`
    Run `conan install` using values from |nvim-conan-config-file|.

`build`
    Run `conan build`. If a new `compile_commands.json` is produced, the plugin
    links the newest one into the project root.

`lock`
    Run `conan lock create` for the configured recipe.

`:Conan create [args...]`
    Run `conan create` for the configured recipe: >
      conan create [recipe] [profiles] [optional build policy] [args...]
<
    For example: >
      :Conan create --version=1.2.3
<

`:Conan export [args...]`
    Run `conan export` for the configured recipe: >
      conan export [recipe] [args...]
<
    For example: >
      :Conan export --user=alice --channel=stable
<

`:Conan export_package [args...]`
    Run `conan export-pkg` for the configured recipe: >
      conan export-pkg [recipe] [args...]
<
    For example: >
      :Conan export_package --output-folder=build/package --user=alice --channel=stable
<

For these commands, additional arguments retain their original order, remain
separate literal argv elements, and are passed directly to Conan without shell
interpretation.

BREAKING CHANGE: `:Conan export alice stable` and
`:Conan export_package alice stable` are no longer rewritten as user/channel
flags. Use explicit Conan flags instead: >
  :Conan export --user=alice --channel=stable
  :Conan export_package --user=alice --channel=stable
<

`search {pattern} [remote]`
    Search Conan packages asynchronously and open Telescope results. Press
    <Enter> in the picker to copy a reference, or <C-i> to insert it.

`upload`
    Pick a remote and a cached reference with Telescope, then run
    `conan upload ... --confirm`.

`reconfigure`
    Rebuild the project configuration interactively, including an optional
    free-form build policy.

==============================================================================
5. Configuration                                     *nvim-conan-configuration*

Project settings are read from either supported location: >
  conan-config.json
  .vscode/conan-config.json
<
                                                        *nvim-conan-config-file*
Typical shape: >
  {
    "recipe": ".",
    "version": "2.0.0",
    "profile_build": "default",
    "profile_host": "default",
    "options": {},
    "conf": {}
  }
<

The config is created interactively from the current working directory and is
used by `install`, `build`, `lock`, `create`, `export`, and `export_package`.

`build_policy` is optional. Automatic first-time configuration does not set it;
|:Conan| `reconfigure` accepts a free-form optional value after the profiles
are selected. Enter only the portion following `--build=`, such as `missing`
or `missing:zlib/*`. A missing, empty, or blank value omits `--build`; a
configured value adds `--build=<value>` to `install`, `build`, and `create`.
For example: >
  "build_policy": "missing"
<

==============================================================================
6. Health check                                         *nvim-conan-checkhealth*

Run: >
  :checkhealth conan
<

The health check reports:
- whether Neovim satisfies the minimum version
- whether `conan` is executable and is Conan 2.x
- whether telescope.nvim modules required by the plugin are available
